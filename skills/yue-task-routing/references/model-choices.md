## Optional combination: one owner, help as needed

When Yue asks for “Sol 主做，Astra 按需帮忙，独立小活交给 Luna Max” or describes the equivalent combination:

- Sol medium is the continuing execution candidate; do not silently change the current selector. If the current parent remains Astra, a Sol child owns only its assigned implementation scope and returns results; Astra retains parent accountability. Use a real handoff only when explicitly arranged.
- If direction is unsettled or a wrong approach would be costly, ask Astra for the smallest actionable plan: outcome, approach, consequential tradeoff, and acceptance. Trial medium first; high/xhigh only for demonstrated complexity or explicit selection, not by habit. An already adequate plan needs no rewrite.
- Sol carries out the authorized work and its normal checks. Use high only for a concrete unresolved difficulty or Yue's selection, not for every multi-file task. Plain reports and bounded small fixes may still go directly to Luna Max.
- Luna Max may take independent work with clear input, output, and disjoint write scope when it can plausibly meet acceptance and delegation is authorized. Sol keeps shared-state decisions. Do not re-delegate each step or outsource an urgent dependency merely to complete the model chain.
- Astra reviews only when explicitly requested or independent judgment has material value. Supply the existing plan, key diff, completed validation, and remaining risks. Return goal alignment plus PASS/CHANGES_REQUIRED and at most three material findings; no routine retesting. The execution owner fixes actionable issues; re-review only the changed risk when necessary, not the whole pipeline.
- Native nested calls may be unavailable. Do not simulate them with unrelated CLI/API processes or silently replace models. Keep supported work with the current owner; a supported parent can dispatch the independent contribution directly without adding a ceremonial coordinator.

This is an opt-in recipe, not evidence that a three-model chain is more economical. A simple “省额度” does not activate all roles. Existing model selection, permissions, and the user's final outcome remain unchanged.

## First small trial (2026-09-05)

Astra medium and Luna Max each completed one identical synthetic local repair and one fixed-input status report with no corrective rerun. Both repairs passed the same 12 acceptance cases. Recorded elapsed times: Astra 65.4s / 14.5s, Luna 87.7s / 25.5s (repair / report), including startup and scheduling. Runtime records confirmed both model/effort settings. This is one observation per task, not a stable speed ranking or production benchmark. Attributable dollar cost and weekly quota cost remain unknown; different cache hits prevent naive token-to-price comparisons. Child startup input remained around 35k tokens even without inherited conversation history: do not delegate tiny work automatically. These tests did not evaluate this Skill's routing behavior or orchestration benefit.

Later the same day, Sol medium completed the same seeded repair and task prompt, passing the same 12 acceptance cases without correction in 64.7s. Runtime metadata confirmed `gpt-5.6-sol` / `medium`. This was a sequential follow-up under a changed startup context, not a concurrent controlled comparison. No additional report task or multi-model chain was tested. It supports trying Sol medium for bounded implementation, not claiming better cost, general superiority, or production readiness.
